# 🌅 WakeTune 2.0 — מפרט מוצר "Morning OS"

הגדרת הגרסה הבאה, לפי סדר העדיפויות: **קודם כל להעיר בבוקר**, אחר כך שגרת בוקר.
כל פיצ'ר מסומן: ✅ אפשרי במלואו · ⚠️ אפשרי עם סייג · והטכנולוגיה שנבחרה.

## Phase 1 — "השעון שאי אפשר לרמות" (המינימום)

### 1.1 נגינת פלייליסט בפול ווליום, ללא הפסקה — Spotify + Apple Music

**מה המשתמש חווה:** מכין פלייליסט השכמה מראש. בשעת היעד המוזיקה מתפוצצת
בפול ווליום ולא נעצרת עד הוכחת התעוררות.

| רכיב | סטטוס | טכנולוגיה |
|---|---|---|
| Spotify — כניסת משתמש עם החשבון שלו | ✅ קיים כבר בקוד | OAuth PKCE (`spotifyAuth.ts`) |
| Spotify — נגינת פלייליסט (לא שיר בודד) | ✅ שינוי קטן | `PUT /me/player/play` עם `context_uri` של הפלייליסט במקום `uris` |
| Apple Music — כניסת משתמש | ✅ | iOS: **MusicKit** נייטיבי (`MusicAuthorization`); אנדרואיד: Apple **MusicKit for Android** SDK. דורש Apple Developer Token (חתום JWT) — אין מגבלת 25 משתמשים ואין תהליך אישור כמו Spotify |
| Apple Music — נגינה | ✅ (למנויי Apple Music) | iOS: `ApplicationMusicPlayer` מנגן **בתוך האפליקציה** — יתרון על Spotify! אנדרואיד: MediaPlayback דרך ה־SDK |
| פול ווליום כפוי | ⚠️ | אנדרואיד: הגדרת `STREAM_ALARM`/`STREAM_MUSIC` למקסימום דרך native module + Foreground Service. iOS: אפשר לקבוע volume של הנגן בתוך האפליקציה; את ווליום המערכת אפשר להרים רק כשהאפליקציה פעילה |
| "ללא הפסקה" כשהאפליקציה נהרגה | ⚠️ מגבלת פלטפורמה | אנדרואיד: full-screen intent מחיה את האפליקציה → מוזיקה מתחילה תוך שניות ✅. iOS: אם force-quit — צליל notification עד שהמשתמש פותח (כמו כל המתחרים). מיטיגציה: Critical Alerts entitlement + הנחיות onboarding |

**החלטת ארכיטקטורה:** ממשק `MusicProvider` אחיד (`connect() / getPlaylists() /
play(playlistId) / stop() / setVolume()`) עם שני מימושים — `SpotifyProvider`
(קיים) ו־`AppleMusicProvider` (חדש, native module). המשתמש בוחר ספק ב־onboarding.

### 1.2 משימה: 10 שכיבות סמיכה מאומתות במצלמה — CV מקומי

**כן, זה אפשרי לחלוטין, והכל on-device:**

- **טכנולוגיה:** `react-native-vision-camera` (frame processors) + מודל pose
  estimation קליל: **MoveNet Lightning (int8, ~3MB)** או **MediaPipe BlazePose**
  (33 נקודות שלד). שניהם רצים 30–60fps על טלפונים מודרניים, ללא רשת.
  - [מדריך VisionCamera + TFLite של יוצר הספרייה](https://mrousavy.com/blog/VisionCamera-Pose-Detection-TFLite)
  - [react-native-mediapipe — pose landmark detection](https://cdiddy77.github.io/react-native-mediapipe/docs/api_pages/pose-landmark-detection/)
- **אלגוריתם ספירה (מכונת מצבים):** זווית המרפק (כתף–מרפק–שורש יד) —
  ירידה מתחת ל~90° = DOWN, חזרה מעל ~160° = UP. מחזור DOWN→UP מלא = חזרה אחת.
  דרישות איכות: שתי נקודות המרפק בביטחון גבוה, ציר כתף–ירך יציב (גב ישר),
  קצב סביר (חזרה ≥ 1 שנ') — מונע רמאות של נדנוד הטלפון.
- **חוויית משתמש:** הטלפון נשען על הרצפה/קיר, המסך מציג ספירה ענקית 3/10 +
  שלד live. fallback אם אין אישור מצלמה: משימת הקלדה.
- **פרטיות:** אפס הקלטה. הפריימים מעובדים בזיכרון ונזרקים. בדיוק כמו שמפרסמת
  המתחרה [Pushy](https://pushupsalarm.com/) — וזה גם קו השיווק שלנו.

### 1.3 משימה: ריקוד מאומת במצלמה — CV מקומי

**גם זה אפשרי — ואף מתחרה לא עושה את זה (בידול ייחודי):**

- אותו pose model. מדד "אנרגיית תנועה": סכום מהירויות של נקודות מפתח
  (ידיים, כתפיים, ירכיים) בין פריימים, מנורמל לגודל הדמות בפריים.
- תנאי הצלחה: אנרגיה מעל סף במשך X שניות מצטברות (לפי קושי: 15/25/40 שנ'),
  עם דרישה לתנועת **ידיים וגם גוף** (שלא יספיק לנפנף אצבע).
- גרסה מתקדמת (Phase 3): התאמת התנועה לקצב השיר (BPM מ־Spotify audio analysis
  אם זמין, או זיהוי beat מקומי).
- fallback בלי מצלמה: משימת התנועה הקיימת (אקסלרומטר).

### 1.4 משימה: הקלדת משפט באנגלית ממאגר

✅ **קיים כמעט לגמרי** — `lyricsChallenge.ts` כבר תומך במשפטים; נרחיב את
`WAKE_SENTENCES` למאגר של 200+ משפטים באנגלית מדורגים לפי קושי (קל: 6–8 מילים,
קשה: 14+ מילים עם פיסוק), והקלדה מדויקת לפי סף הדמיון הקיים.

## Phase 2 — שגרת הבוקר

### 2.1 צילום ארוחת בוקר → לוג נוטריינטים

- **זרימה:** אחרי סיום המשימה מוצג "צלם את ארוחת הבוקר 📸" → תמונה → זיהוי
  מנות → פירוק תזונתי (קלוריות, חלבון, פחמימה, שומן) → נשמר ליומן מקומי.
- **טכנולוגיה — שתי אפשרויות:**
  1. **API ענן לזיהוי אוכל** (מומלץ להתחלה): שירות ייעודי או מודל vision
     (למשל Claude API עם תמונה) שמחזיר JSON של מנות ומאקרו. דורש רשת + הסכמה
     מפורשת שהתמונה נשלחת לעיבוד. עלות: סנטים בודדים לתמונה.
  2. **מודל מקומי** (בהמשך): מודלים כמו MobileNet-Food קיימים אבל דיוקם נמוך
     משמעותית — לא ל־MVP.
- **לקח מ־Cal AI** ([ניתוח הדיוק](https://www.eesel.ai/blog/cal-ai-pricing)):
  להציג **טווח** ("450–600 קק"ל") + עריכה ידנית בהקשה, לא להבטיח דיוק מוחלט.
- **מודל נתונים:** `MealLog { id, photoUri(local), items[{name, kcalRange, protein, carbs, fat}], loggedAt }` — נשמר מקומית; ללא ענן משלנו.

### 2.2 אגנדת היום — יומן ומייל

- **שלב א — יומן (קל, מומלץ להתחיל כאן):**
  - iOS: **EventKit** — גישה לכל היומנים במכשיר (Google/iCloud/Outlook שכבר
    מסונכרנים), אישור מקומי אחד, בלי OAuth בכלל.
  - אנדרואיד: **CalendarProvider** (`READ_CALENDAR`) — אותו סיפור.
  - כלומר: אגנדת יומן **בלי שום שרת ובלי אימות Google** — הכי פרטי שיש.
- **שלב ב — מייל (כבד יותר):** Gmail API בהיקף readonly הוא **restricted scope**
  שדורש אימות אבטחה שנתי של Google לאפליקציות ציבוריות — תהליך יקר. חלופות:
  להתחיל עם "סיכום מהיומן בלבד", או לחבר את חשבון המייל דרך integration
  אופציונלי בהמשך.
- **מסך "הבוקר שלך":** אחרי המשימה (ואופציונלית הארוחה): 3 הפגישות הקרובות,
  זמן יציאה מומלץ, ומשפט מוטיבציה. בלי פיד אינסופי — מסך אחד וסיימת.

## עקרונות שלא מתפשרים עליהם

1. **כל ה־CV מקומי, אפס שמירת וידאו** — גם פרטיות וגם מסר שיווקי.
2. **תמיד יש דרך לכבות** — כפתור החירום נשאר; כשל מצלמה ⇒ משימת הקלדה.
3. **ההתראה תמיד מצלצלת** — גם בלי רשת, בלי פרימיום, בלי מצלמה (צליל מקומי).
4. **ווליום** — "פול ווליום" עם רמפה של 5 שניות בתחילת הנגינה (בטיחות שמיעה).
